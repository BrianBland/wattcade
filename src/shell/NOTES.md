# shell + debug (Agent E; no open contract requests)
## Layout
- HUD Insets retain the conservative bottom band; optional measured child rectangles update on content/legend changes, including in warmup. TD alone opts into shaped coverage. `hud/insets.test.ts` and GameHost tests cover offset/clipping/fallback and same-envelope shape changes.
- Locker groups: Ride, Rider, Company & effects, Identity; independent wardrobe slots and only the current catalog. Ships are selected in Cadenza. Controller grid columns follow the phone/desktop layout.
- `src/main.tsx` -> `shell/App.tsx` (screen state machine) + `debug/DebugOverlay.tsx`. CSS in `src/styles/main.css`.
- `shell/services.ts` is the ONLY file importing core/input/progression/devices (adapters, singletons `input`, `dataHub`). Everything else uses it.
- `shell/screens/`: ProfilePicker, ProfileEditor (+backup export/import), Connect, ArcadeMenu, GameHost, PauseMenu, Summary, Achievements.
- Pure/tested: `shell/nav.ts` (grid nav reducer), `shell/format.ts`. `shell/useMenuNav.ts` drives InputHub.beginTick itself in menus (D-pad/A/B + Enter/Esc).
- `debug/`: `panels.tsx` (device, derived, controller, mixer, tuning), `TrainerTest.tsx`, `types.ts` (`DebugSnapshot`, `DebugActions`), polled at 5 Hz from `services.debugSnapshot()`.
- Flow: connect -> profiles -> menu -> game -> summary. On quit: `session.finish()`, SessionStore.save, `awardSession`, profile saved.
- No device connected (or Fake toggle on) => session uses core FakeBike with chosen script. Real devices => shared `dataHub`.
- Pause (system `pause`): `session.pause()` + mixer panic; resume releases. Wake lock requested in GameHost.
- Debug overlay: system action `toggleDebug` (persisted); sets `input.debugOpen` (shifters -> difficulty/timeScale). Trainer test via mixer effect `trainer-test`; fake sliders edit `fakeBike.manual`.
- HUD chip shows ride time (`bike.activeSeconds`, pedalling time). Pause menu has a Sound on/off toggle (`wattcade.sound` flag).
- `src/audio/sfx.ts`: shared WebAudio synth (`play(name, { minGapS })`, `unlockAudio()` called by GameHost on mount/gesture). Renderers import it; nothing runs in Node.
- GameHost passes `send` to `renderer.mount`, forwarding to optional `GameSim.receive(action)` (canvas UI taps).
- UI kit (`components/ui.tsx`): Panel, KeyHints/Key (Ride colours), ScreenHeader, Field (focusable row), Stepper, Choice, Toggle, CountUp, Spinner; `Bits.tsx` Btn plays `uiSelect`. Shared flat primitives/tokens in `src/ui/`; guide: `docs/UI_STYLE_GUIDE.md`, gallery: `/dev/ui-kit.html`. Legacy game-owned styles remain separate.
- `useMenuNav(count, layout, onSelect, onBack, enabled, { initial, onAdjust, onY })`: layout = cols or row lengths (`navRows`); onAdjust takes left/right on value rows; UI sounds (`uiMove/uiSelect/uiBack/uiTick/uiWake`) play from here.
- Editor: rows from pure `editorFields.ts` (tested); left/right adjust, A toggles/cycles/types, delete needs a second A. Pause: difficulty reads back the session mixer (`getDifficulty`). Summary: staged reveal, ride chart, XP count-up/fill. Locker (`screens/Locker.tsx`) and reward picks (`screens/RewardPick.tsx`; Summary routes there when `award.picks > 0`); `components/RiderAvatar.tsx` draws the rider (shared rAF loop, `still` for thumbnails; Locker defers offscreen canvases via IntersectionObserver, skips unchanged resize paints, releases backing stores on cleanup, and removes per-tile backdrop blur to reduce iOS stalls) in place of the old colour dot; the lobby renderer remounts when the look changes. Achievements: views (group, progress, secret) come from `services.achievementViews`; grouping + closest goals in `achievementGroups.ts`. Picker previews the last rider; touch selects before Ride, controller A rides/Y edits. Flat connection/roster/pause/notification chrome lives in `chrome/` (see its NOTES).
- Arcade picker (`ArcadeMenu` + pure `arcade.ts`, tested): one-row looping carousel (`carouselSlots`/`loopOffset`; a card wrapping ends skips its transition), selection centred/enlarged with clip (`public/cards/<id>.mp4`, recorded by `scripts/capture-cards.ts` via `dev/capture.html`), tags, blurb, `progressLine(save)`, `ridesLine` (time/kJ from `services.gameRides`), last played; side cards = poster + title. `drawCard` is the fallback art. Order: `orderGames` (lastPlayed desc, registry order = polish). Nav rows [top bar, 1]: ◀▶ on the row roll it via onAdjust.
- Game flow (GameHost phases): intro card (`game/GameIntro.tsx`: blurb, target zone, controls via pure `controlGlyphs.ts`; A start, B back to menu without saving, explicit Start with no automatic timeout) -> 3-2-1-GO with the session `idle()`-ing and the trainer held neutral (panic) -> GO releases it and `mixer.rampIn()` -> play (mid-ride toasts every 10 s from `previewAward`: achievements, level-up, 10-min milestones) -> optional game recap (`GameRenderer.ending()` returns its seconds, ≤ 15, A skips; `game/ending.ts`) -> result banner (`game/ResultBanner.tsx`, 4 s or A) -> summary. Pause adds Controls (intro card as help) and Restart (saves the ride, new run via `screen.run`). A game with its own pre-game menu (`sim.inMenu()`: Cadenza, Dungeon, Starfighter, Watershed) opens in that menu (`countGate.openingPhase`), then shows gameplay controls before countdown; pause works there too (`canPause`), its Exit game leaves without saving, and the trainer stays neutral until GO.
## Gaps
- HUD trainer state: with gears off, show last commanded ERG watts / RES range percentage / SIM grade, or Idle/Offline; use mixer.command (includes caps/difficulty/ramp), not measured power or raw effect. Both portrait and landscape use one central gear ± pair when enabled; no duplicate hood gear controls. Changing to trainer mode cancels held shifts; game-specific shifters remain. Mapped face buttons show action text instead of letters; controls may supply `shortLabel` for readable key/group/paddle captions (e.g. Boost/Slow/Shop), retaining full `label` in help, accessibility and tooltips. Color/cooldowns retained. Desktop primary readings share a 28px-high centerline, independent of FTP/cadence sublabels. Phone 320/390px and desktop gear/trainer captures inspected. Real Bluefy remains unverified.
- Fake bike keys (W/S cadence, E/D power, R/F HR via event.code, `shell/fakeKeys.ts`) active in GameHost and the warm-up stage (`fakeKeysDom.ts`); first press switches FakeBike to manual seeded from current raw values; hint shown in the game host when fake.
- In-game HUD (`shell/hud/`): one instrument bar with on-demand history; Auto follows connected controllers and shows only colored cooldown/trigger indicators. Touch retains floating controls. Complete bindings and physical maps live in start/pause help; fake-bike help stays outside the persistent HUD. Auto/Touch/Controller preference is `wattcade.hudLayout`; see `hud/NOTES.md` for input cancellation, insets and validation.
- HUD layout: .mount is edge-to-edge; HUD floats over measured --hud-h; GameHost passes renderer Insets (src/games/insets.test.ts). At ≤700px or portrait: three primary readings with 9–14px icons, time + gear/trainer row, zone bar; no history/FTP/fake hint/wrapped target copy. Cadence target replaces rpm (direction + green/yellow); power targets replace W with floor watts. Larger controller keys; non-gear shifters stay above clusters, analog indicators hide. Landscape retains history, evenly distributes five intrinsic-width readouts, hides the duplicate zone icon, and aligns zone/label/history tracks full-width; geometry checked at 701/900/1280px. Verify: `npx tsc --noEmit -p .`; `npx vitest run src/shell src/input src/games/insets.test.ts`.
- Warm-up lobby (`warmup/WarmupStage.tsx`): rendered behind every non-game screen. Runs a lobby session of `lobbyGame` (services `startLobby/stopLobby`), draws its renderer full-bleed, owns keyboard/gamepad/fake keys and the InputHub tick. Restarts (keeping road position) on rider/device/fake changes. Guest (no profile) on profiles/editor; demo (fake) rides never credit.
- Menu input: `menuInput.ts` is the single press source for `useMenuNav` (stage delivers presses buffered across sim steps; otherwise, e.g. the in-game pause menu, it ticks the hub itself). `setMenuGate` lets App swallow the waking press.
- Warm-up credit: real devices and >= 2 min pedalling (`WARMUP_CREDIT_S`). Credited on: game start (before the game session), arcade-menu "End ride" (-> Summary), rider/device change, 3 min stopped (auto-save), and next launch via a localStorage checkpoint (`wattcade.pendingRide`, every 20 s / on hide). Toasts: `components/Toasts.tsx`.
- Screensaver: on profiles/menu/achievements/summary, 25 s without menu input fades the screens out (HUD stays, legend hides); the first tap or nav press only wakes. Shifters never wake; HUD taps open/wake the menu. HUD centre button is configurable (`menu` getter).
- App keeps `profileRef` so async credit and game saves always apply to the latest profile.
- Road: Hills/Flat toggle in the arcade menu (`warmup.hills` tunable, saved per rider).
- Tests: `npx vitest run src/shell src/debug`.- Drive-In (`shell/drivein/`, see SPEC §6.6): `channels.ts` (lineup, dial reducer, saved state), `layout.ts` (`screenRect`, `easeRect`), `playback.ts` (watchdog), `store.ts` (per-rider state; `handleChannelPress` for Y/Z), `DriveInScreen.tsx` (video, static, OSD, chip, bar; its `api.tick()` is called by `WarmupStage` before each canvas render), `staticFx.ts`. 📽 button = last item of the ArcadeMenu top bar; while on, the carousel is replaced by a lone 📽 toggle (`.di-toggle-row`, measured with `.topbar`/`.carousel` by `measureMenu`). App's menu gate lets Y/Z through without waking; taps inside `.drivein` don't wake either. Video only shows on the `menu` screen.
- Units: imperial by default (including legacy profiles); per-player Units choice precedes numeric editor rows. Weight converts lb ↔ stored kg; lobby, summary and achievement measurements follow the saved choice. Lobby renderer remounts on unit changes without restarting the ride. Visible UI copy uses American English (Color, Center, gray, analyzing, pedaling). Internal identifiers and save keys are unchanged. Optional media extension on Connect; app-wide settings, tab token, buffered online queues (`rollingMediaRun`).
- Saved setup: `savedSetup.ts` stores origin-local trainer/HR/two Ride IDs shared by all players. `restoreSavedSetup()` runs once on startup via getDevices, never a picker; missing grants/failed connections allow manual selection.
- Startup: Connect → ProfilePicker → Arcade; reopening Connect returns to Arcade when a player is selected. Tests: savedSetup.test.ts + App.test.tsx.
- HR pool: remembers multiple IDs, last-used first; tries alternatives on startup. Saved-watch buttons switch without a picker; Add watch authorizes another. Only one HR watch is active; not tied to player profiles.
- Restore HR before trainer/controllers so their setup cannot block watch selection. Saved-watch attempts show the watch name and GATT step; disabled buttons explain that connection is pending. DOM tests cover non-bubbling watch clicks. HR feedback identifies automatic connection vs manual retry and increments each attempt even when Bluefy returns the same error. Select watch again explicitly opens the picker; saved retries never do.
- Bluetooth foundation (`docs/BLUETOOTH.md`): role cancellation/ownership, subscriber cleanup, finite recovery and local log export. Saved GATT connections use savedDiscovery.ts: when watchAdvertisements exists, wait up to 10 s for an advertisement, then abort scanning; unsupported browsers connect directly. Bluefy HR reload probe succeeded with this sequence; trainer/Ride and app restart still need hardware tests.
- Unified HUD/controllers: full-sized keys in transparent controller containers, restrained mapped accents, distinct held/focus states; effort text below the bar follows the original low-start/high-end target anchoring; unassigned paddles/shifters omitted. Gear captions retain per-side assignments; mixed Dungeon actions remain. - Music search on touch devices (`media/useSearchKeyboard.ts`): fit the visible viewport above the keyboard; hide header/tabs/provider/preview/queue/legend and bike HUD while searching, keep the field and scrolling results visible, restore on dismissal. Enter/Search blurs the input and submits valid online queries; composition Enter is left to the IME. Viewport lifecycle tests plus browser checks at iPad landscape/portrait sizes (simulated keyboard).
